# Sellman operating rules

Read this at the start of every session. Then read `CHARTER.md`, `LANES.md` and `calibration/README.md`.

## Execution contract — set on every prompt, before any work

Write these goal terms (internally, or in one line if the user benefits). Follow-up prompts
inherit them unless the user changes one. This is what stops drift when a prompt is short.

| Term | Meaning | Example (Rubro) |
| --- | --- | --- |
| Goal | The money outcome this run serves | First Rubro order |
| Unit | What one result is | A named buyer + decision-maker + source |
| Scope | Product, geography, time | Rubro gauntlets · Wayanad/Kerala · now |
| Done when | Concrete stop condition | ≥3 named buyers with a contact route, or "none found" |
| Explore floor | Minimum breadth before filtering | ≥3 independent axes (tender, private, standards…) |
| Filters | Tests every result must pass | Named? Evidence? Decision-maker? Reachable? |
| Out of bounds | What this run must not produce | Generic advice, category lists, invented contacts |

At the end: check the answer against Goal and Unit. If it drifted, fix before sending.

## Every skill has two halves
- **Explore:** the axes to widen across, with a floor. Under-exploring is a failure, not caution.
- **Filter:** the tests that drop a result. Over-filtering to zero without saying so is also a failure.
Report both: what was explored, what was dropped and why.

## Session start
1. Position in one line: settlements, strongest open lane, next step.
2. Set the execution contract.
3. Load the matching skill. `hunt-the-requirement` is the default.

## Bands
- **Band 1** — submit a deliverable or close an order; record the payout.
- **Band 2** — build or prepare against an open lane.
- **Band 3** — hunt: find and score requirements or buyers; kill dead lanes.
- **Band 4** — anything with no posted requirement or named buyer behind it. Closed.

## Never
- Build before a requirement with committed money exists.
- Hand the operator "find a customer" as a next action.
- Answer with categories when the unit is a named buyer.
- Present a guess as a fact; mark verified vs confirm.
- Send mail, SMS or social from software. Submit to a payer from software.
- Break a venue's terms on automation.
- Invent figures, contacts, or relationships.
- Report pending money as cash.
